# QQ音乐「一起去现场」3 分钟演示脚本

> 演示主线固定为：`演出详情 → 描述同行需求 → 四项摘要确认 → 双轨动态匹配 → 同频汇合 → 同行票根 → 双方确认 → 消息里的同行房间`。演示过程中不再返回首页，也不会把用户丢进超长单页。

## 0:00–0:20｜首页：两条轨道尚未汇合

停在首页首屏（390×844 无需滚动）：两条声波轨道左右分开，中间是一条虚线留白，轨道上漂着少量头像节点，徽标写着「两条轨道尚未汇合」。

主标题：「去现场之前，先找到和你听同一首歌的人。」
副标题：「AI 根据音乐口味、同行方式与安全边界，寻找同场同行者。」

点击唯一主按钮「开始同频」，进入夜航计划演出详情。

## 0:20–0:40｜演出详情 + 音乐画像授权

展示歌手、时间、地点、热门歌曲和安全提示，说明这是 QQ音乐演出详情概念页，新入口是「一起去现场」。

授权页展示收藏歌曲、常听歌手、歌单标签、关注演出和近期播放；先演示「暂不授权」的停止状态，再一键授权。全站只在顶部保留一个「概念功能 Demo」标签，页面正文不再重复 Demo 声明。

## 0:40–1:10｜描述同行需求 → 四项摘要确认

输入：「想找两个也喜欢《夜航的信》和星野回声的人一起候场，交流慢热一点，只在公开场合见面。」

点击「让 Agent 理解需求」，在同一页确认四项摘要：音乐暗号、同行方式、现场氛围、安全边界。有不对的地方点「有一处不对」修改。技术说明与工具调用收进可折叠的「查看 Agent 工作过程」。

## 1:10–1:40｜双轨动态匹配：候选头像从四周靠近

点击「开始匹配」。屏幕中心是用户头像与两条反向旋转的音乐轨道，候选人头像以声波节点从四周出现并向中心靠近。五个阶段依次点亮，每个阶段只说一句话：

读取音乐画像 → 寻找同场听众 → 检查安全边界 → 核对同行方式 → 生成破冰理由

没通过安全硬条件的人只会柔和淡出，没有红叉、没有「淘汰」文案。展开「查看 Agent 工作过程」才显示真实工具名、输入输出摘要、耗时与 fallback，评委可以当场核对真实性。

## 1:40–2:15｜同频汇合 + 同行票根

跑完后先播 600–900ms 汇合动画：两条声波从左右进入，在共同歌曲封面处汇合，双方头像移动到交汇点，出现「发现同频同行者」与真实综合匹配度「同频 86%」。

页面只展示三条最重要的信息：共同歌曲、同行目的、安全边界是否一致，以及一句由真实模型结果生成的匹配理由（最多两行，不含技术术语）。

动画结束后浮出可展开的**同行票根**：演出名称与时间、双方头像、共同歌曲、同行方式、公开集合原则、双方确认状态。

## 2:15–2:40｜暂不同行 / 换一位 / 发出同行邀请

底部三个操作都必须真实可用：

- 「暂不同行」弹出理由（音乐不搭 / 同行方式不同 / 人数不合适 / 其它），只记录到下一轮匹配，**不通知对方**；
- 「换一位」真的切到下一位候选人，票根与匹配理由同步刷新；
- 「发出同行邀请」后按钮变为「等待对方确认…」，**双方确认前不会创建房间**。

## 2:40–3:00｜双方确认 → 消息里的同行房间

对方确认后出现「进入同行房间」。房间是消息模块里的一个群聊：顶部左侧「‹ 消息」返回，一行集合状态卡点开是集合详情（地图、集合时间、成员确认、到达状态、安全说明），中间只留真人聊天，候场任务 / 共享歌曲 / Agent 帮写放在输入栏「＋」，举报与屏蔽要长按消息，消息免打扰与退出同行在右上角「···」。

收束：房间只服务演出前和候场期间，活动结束 24 小时后自动归档；演示到房间建立成功结束。

## 附：逐帧回放

本机没有 ffmpeg，因此用 CDP 逐帧抓取代替 mp4：`cd frontend && node scripts/demo-capture.mjs` 会按 420ms/帧录制「开始同频 → 发出同行邀请」整条链路，输出到 `docs/demo-frames/`，再用 `docs/demo-replay.html` 播放（可直接用浏览器打开）。
## 附：双身份人工演示（两个浏览器真人互发消息）

不需要 mock，也不需要 Agent 冒充对方：准备一个固定的演示房间，两个浏览器凭同一个 roomId 进入，各自用一个 Demo 身份手动收发消息。

1. 先准备房间（每次演示前执行一次，会清空该房间的历史消息）：

```bash
cd backend
.venv\Scripts\python.exe scripts/seed_demo_room.py
```

2. 两个可直接复制打开的地址（390×844 移动端视口）：

- 浏览器 A（普通窗口，身份 Demo访客）：`http://127.0.0.1:5173/#/room/room-demo-dual?demoRole=visitor`
- 浏览器 B（Edge / 无痕窗口，身份 写歌的江离）：`http://127.0.0.1:5173/#/room/room-demo-dual?demoRole=jiangli`

3. 身份只存在各自 tab 的 `sessionStorage`（键 `sfl.demo.role`），两个浏览器互不覆盖；页面顶部会显示「当前身份：Demo访客 / 写歌的江离」。

4. 身份入口只在 development / demo 模式出现（`import.meta.env.DEV` 或 `VITE_DEMO_MODE=true`），普通生产构建不会打包这段 UI。

5. 自动化验收：`cd frontend && node scripts/acceptance-demo-roles.mjs`（两个隔离 Chrome 实例，验证 A→B、B→A、双方刷新恢复、无第三方自动回复）。

6. 消息一律由真人手动发送，后端只落库并回显，绝不调用模型或替对方自动回复。
